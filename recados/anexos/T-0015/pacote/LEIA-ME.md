# T-0015 · Pacote de governança (3 agentes novos) · para o `po`

Num branch novo do `aloirr/bapajudacatalogo` a partir do `main` (os três arquivos base deste pacote são iguais ao `origin/main` em 20/11/2026), copie os três arquivos de `pacote/.claude/agents/` (`corretor-redundancias.md`, `design-de-marca.md`, `designer-ux.md`) para `.claude/agents/` e aplique os patches na raiz do repositório, nesta ordem, com `git apply`: `donos.json.patch` (as 3 regras novas, `docs/qualidade/redundancias/**`, `docs/marca/**` e `docs/ux/**`, entram antes de `docs/**`, porque vale a primeira regra que casa), `coord-lib.mjs.patch` (os 3 nomes em `AGENTES_DO_TIME`) e `CLAUDE.md.patch` (11 agentes, Conferência, Caminho e a regra de merge do PO); os três passaram no `git apply --check`. Faça tudo num PR só de governança, com o commit que tem os 5 arquivos (3 agentes + `.coord/donos.json` + `scripts/coord-lib.mjs` + `CLAUDE.md`); quando o CI estiver verde e a revisão LIBERADO, você autoriza em recado ("autorizo o merge do PR #N no commit <sha>") e o `gerente-projetos` faz o merge. Depois desse merge, o gerente aplica o `README.md` deste pacote no `.coord/README.md` num PR dele (o arquivo é dele). Atenção: o guardião (`.claude/hooks/guarda-bash.mjs` e `autorizacoesDoAlexandre` em `.claude/hooks/guarda-merge-lib.mjs`) ainda só reconhece o "autorizo o merge" vindo do Alexandre, então, até o código mudar, a autorização do PO não destrava o guardião sozinha; e o `BAP_AGENTES_TESTE` do `.github/workflows/ci.yml` lista agentes de outro projeto (não quebra nada, mas fica para outra tarefa).
